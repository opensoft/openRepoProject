## Context

See proposal.md for motivation and the disposable-cache specification for the
observable contract. `project clean` currently treats every ignored path as a
single opaque blocker, even when Python generated bytecode while running the
CLI or its test suite.

## Goals / Non-Goals

**Goals:**

- Let an already-confirmed worktree removal clear only known reproducible
  Python bytecode artifacts as part of its plan.
- Preserve the read-only default and make reports explain which ignored paths
  are disposable versus blocking.
- Strengthen the surviving-worktree execution path for final branch cleanup.

**Non-Goals:**

- Add a broad `git clean` mode, a separate cleanup command, or automatic
  deletion during a read-only audit.
- Auto-delete dependencies, virtual environments, editor settings, test data,
  coverage artifacts, symlinks, or any unlisted ignored file.
- Fetch, push, merge, force-delete, or remove a remote branch.

## Decisions

1. **Use a fixed, code-owned allowlist.** Initially it recognizes only actual
   non-symlink `__pycache__` directories and regular `.pyc`/`.pyo` files under
   the selected worktree. This is narrow enough to be independently verified;
   an extensible classifier is preferred over trusting every Git-ignored path.

2. **Collect exact paths with Git status and retain them in the cleanup
   signature.** The report exposes all ignored paths, disposable paths, and
   blocking paths. Revalidation compares those fields as well as branch and
   merge evidence, so a same-count path substitution cannot turn an unknown
   file into a deletion target.

3. **Delete exact paths with contained-path checks, not a broad Git command.**
   The confirmation plan lists every disposable path. Execution rejects
   symlinks and containment failures, removes each listed regular file or
   directory, and stops before `git worktree remove` if any cache deletion
   fails. `git clean -fdX` is rejected because it would also delete unknown
   ignored files.

4. **Anchor post-removal Git work to the target-branch worktree.** The caller
   can target the worktree being removed, so later branch operations cannot use
   that vanished path. The cleanup report identifies the surviving default
   worktree and supplies that stable Git command directory.

## Risks / Trade-offs

- [A new generated cache type is not allowlisted] → It remains a visible
  blocker until explicitly reviewed and added with tests.
- [A path is changed after confirmation] → Exact revalidation refuses before
  any deletion.
- [A cache deletion partly completes before an I/O failure] → Worktree and
  branch retirement do not run; only reproducible listed cache artifacts may
  have been removed.

## Migration Plan

Add disposable Git fixture tests for successful cache-assisted retirement,
unknown/symlink blockers, revalidation, failure containment, and cleanup
invoked from the retiring worktree. Update README guidance, run the full
py-bench suite and strict OpenSpec validation, then roll back through a normal
code revert if needed.
