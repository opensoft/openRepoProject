## Council-Identified Constraints

### S-4. The pre-handoff and landing gates check the wrong axes
**Raised by:** systems-architect (S-4, LOW)
**Concern:** D4 gave the cache stage's per-call hand-off as "tens of
microseconds a call, that is tenths of a second in a run". Measured on this
workstation at load average 30 to 37 on 32 cores (Python 3.12.3, a bare
`os.stat` 2.4 to 2.8 us), a call costs 169-224 us through one queue-fed worker
and 393-622 us through a daemon thread per call, the shape of feature 004's
`fs_call`, so the claim was about ten times too low. The plan-time walk's calls
(one per directory open, listing and entry `lstat`, about 4,500 for 4,096
entries) were counted nowhere. Task 2.3 timed the work neither under load nor
through `fs_call`. No gate ran the new porcelain v2 enumeration on the Git 2.36
floor, which feature 004's `git-floor` job tests (Git 2.36.6, `-k test_clean_
-k test_status_ -k test_doctor_`), and task 3.1 named only the two Python
jobs. Nothing is unsafe: a slow stage defers the last targets with exit 1, and a
Git 2.36 difference fails closed to `cache-unverified` or a refusal.
**Design impact:**
- D4 states the measured dispatch cost: 169-224 us a call at load 30 to 37, and
  393-622 us for a thread per call; about 2 s for 8,500 stage calls and 1 s for
  the plan-time walk's 4,500, and the fit is restated with them.
- Task 2.3 re-measures through feature 004's `fs_call`, idle and at the
  workstation's usual load, the plan-time walk included, and checks the
  enumeration's argument vector on Git 2.36.6 by change 1's D17 method (the `! `
  record, the trailing `/` of a directory record, the untracked-files refusal
  and the order of ignored records).
- Task 3.1 and Migration Plan step 7 require green checks on every job of the
  workflow on the realization PR's base, feature 004's `git-floor` job
  included.
- D14: the new tests' names begin `test_clean_`, so that `git-floor` runs them.
