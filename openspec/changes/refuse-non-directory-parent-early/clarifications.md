## Council-Identified Constraints

### N1. The read's shape
**Raised by:** council NOTED list (with verdicts V2 and V5: systems-architect,
adversary-engineer, product-advocate)
**Concern:** The parent's case is needed in two places with different timing:
the question and its Triad refusal, which must not diverge (archived D1), and
the head of the single-repository path, which must read the parent as it is
when that step is reached (V2). One helper should serve both without changing
`known_obstacles()`'s signature or its one list.
**Design impact:** A `parent_case(parent)` helper. `known_obstacles()` keeps
its signature and computes its list once, as today, and that list feeds the
question and the Triad refusal. The bench branch makes one fresh call after
the shape-only flag check (`project:383-384`) and before `choose()`
(`project:385`). The shape branch keeps its own check (`project:371-372`).

### N2. Feasibility facts of the read
**Raised by:** council NOTED list
**Concern:** The walk to the nearest existing path above a missing parent must
terminate, must not add an exception path, must not touch special files, and
must name paths the tests can predict on every CI platform.
**Design impact:** The walk is well defined: the parent is resolved and
absolute, so `parent.parents` ends at the root, which exists. On 3.10 and 3.12
the new call site cannot raise for an unchanged tree: `destination.exists()`
(`project:328`) has already looked up the same ancestors, and an unsearchable
one raises there first, while `is_dir()` and `exists()` ignore the errors a
missing or non-directory component gives. A FIFO is never opened: the reads
are `stat` calls. On macOS a temporary directory resolves under `/private/var`,
so expected paths are the resolved ones (`self.base` already is).

### N3. Blast radius on the existing tests
**Raised by:** council NOTED list
**Concern:** The change must not quietly alter what existing tests pin.
**Design impact:** Exactly one existing test changes,
`test_pty_single_answer_with_a_file_parent_ends_as_the_flag_chosen_path`,
which pins today's late refusal. No existing test builds a parent below a
file. Every existing dry run that exits 0 uses a parent that is not blocked
(`self.base`, or a missing path below it: `tests/test_project.py:526`, `:1195`,
`:1361`, `:1620`, `:1730`). Two-fault invocations change only which sentence
prints; their exit status stays 2.

### N4. The permission facts
**Raised by:** council NOTED list (with V1 and V6; observed by the writer as
uid 1000 on Python 3.12.3)
**Concern:** The term must not promise more than the reads decide. A missing
parent directly below a directory of mode 555 passes `--dry-run` (exit 0) and
is refused after `Create:` and the plan with `REFUSED: [Errno 13] Permission
denied: 'PARENT'`, exit 2. An existing parent of mode 555 passes
`parent.mkdir(exist_ok=True)`, and the generator fails with its own error and
exit status (1 with the test generator). The superuser bypasses mode bits.
**Design impact:** No permission is read; the boundary is stated in the ADDED
requirement and the README, and a test pins the late refusal directly below
an unwritable directory, skipped when `os.geteuid() == 0`. The backstop's text
is unchanged, and only the early refusal says `Nothing was created.`.

### N5. No caller depends on the dry run's exit status
**Raised by:** council NOTED list
**Concern:** A dry run that exited 0 now exits 2 for a parent blocked by a
non-directory; a caller reading that status would change behaviour.
**Design impact:** None migrates: workBenches' `onp` and `new-project.sh`
forward their arguments to `project new`, and workBenches' own test runs a
fake `project`. The change reaches them when workBenches moves its pin.

### N6. The question stays a wasted answer for a blocked parent
**Raised by:** product-advocate, adversary-engineer (with V4)
**Concern:** Under W1 the question is still asked for a parent blocked by a
non-directory, and no answer can succeed: the Triad answer meets its composed
refusal, which does not say that the single repository is blocked too, and
the answer `2` meets the head refusal.
**Design impact:** Accepted as the cost of keeping the ratified question line
reachable (W3 stays rejected). The README says that neither answer can create
anything in such a parent. No line is added under entry 2 (a new form of the
question, beyond this change).
